# ActionWise — dashboard RUNTIME dependencies.
#
# Streamlit Community Cloud installs THIS file, against the Python version
# picked at deploy time (currently 3.14), and Python cannot be changed after
# deployment. Every pin below therefore needs a wheel for that version: with no
# wheel, uv builds from source, and the deploy burns ~50 minutes and then dies.
#
# That is exactly what the old single-file setup did. The blocker was one line —
# `numpy>=1.26,<2.1`, whose upper bound exists for a local Windows reason (see
# docs/WINDOWS-SMART-APP-CONTROL.md). numpy publishes no cp314 wheel below
# 2.3.2, so the cap was unsatisfiable by wheel, numpy 2.0.2 went to a source
# build, the install failed, and the app started against an empty environment
# and died on its first import. numpy is a pipeline dependency, not a dashboard
# one, so it now lives in requirements-dev.txt where the cap costs nothing.
#
# The dashboard reads DuckDB and nothing else. It imports no scikit-learn, no
# lightgbm, no shap, no statsmodels, no girth, no pyreadstat — the whole
# modelling stack is in requirements-dev.txt and has no business here. Actual
# import surface: duckdb, pandas, plotly, streamlit (+ actionwise.config, which
# imports only pathlib). 40 packages resolve here, against 145 before.

streamlit>=1.61,<2
duckdb>=1.5,<2
plotly>=6.0,<8

# Same bound as requirements-dev.txt, so the deployed dashboard runs the pandas
# the pipeline is tested on (2.3.3). It holds on 3.14: pandas ships cp314 wheels
# from 2.3.3, unlike numpy.
pandas>=2.2,<3.0
